# Overlay 91 (the city hall): working notes

One file, `src/overlays/ov091/CityHallScene.cpp`, complete: eight functions, its `.rodata` pool and its strings.
The scene is laid out like overlays 98 and 99 (buttons from tables, labels centred on their positions, a message
window), and the same forms matched. What was new (measured on this file):

- **A branch on flags already tested** (`cmp r8, #5; bne next; bne skip; bl ...`): the second `bne` is a switch
  inside an if on the same value. `if (i == 5) { switch (i) { case 5: state = f(); text = 6; break; } ... }`; the
  switch's compare is folded into the first one's flags and its branch stays. `switch (i) { case 5: ...; default:
  continue; }` gives one `bne` and lets the compiler propagate the constants. The two variables the switch sets
  are declared before the loop, which keeps them in callee-saved registers across it (`mla r0, fp, r4, r9`).
- **A text button's `TextButton_SetMessage` in a loop of its own** (`for (u16 j = 0; j < 1; j++)`, as overlays 39
  and 98 have it) gives the original's `mov r0, r4` early and `add r0, r0, #0x400` late for the button's address;
  the call at the end of the button's set-up loop forms the address in one `add`.
- `Camera *const camera = &gCamera;` and `Light *const` for each light (docs/decompiling.md, ov075-a) held the
  addresses in r4 and r5 across the calls; a plain or reassigned `Light *` was reloaded at each use.
- The scratch byte cleared through `gSceneMemory + 0x3C` (before the friend list, scene 0x1A) is read off
  `gSceneMemory` as overlay 75 does: a view of the block that has the scratch's first byte after `SceneMemory`.
- The last of an `int[8]` table read with a constant index (the text button's next scene, 0x2C) is folded into an
  immediate; the table is still eight entries in the pool, which is how its size sorts it among the 32-byte objects.
